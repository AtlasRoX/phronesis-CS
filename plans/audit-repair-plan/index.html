    Audit repair plan (14 October 2026)

    Combines Phronesis_Full_Audit_and_Repair_Report.md (findings F01–F16, regression cases in its §8) with the six-area code review of the same date. Each workstream owns a disjoint set of files so they can be repaired in parallel; the shared contracts in §1 are fixed first and every workstream codes against them.

    Completion rule (report §13): an item closes when its execution or evidence contract passes a test, not when answer wording becomes more cautious. Preserve working auth, caller-owned dataset resolution, no-synthetic-data guards, precise numeric checks and cancellation/error disclosure.

    1. Shared contracts

    1.1 SimulationPlan (phronesis/agents/query_context.py) — F03, F04, F05, F06, F16

    QueryContext.simulation_plan: Optional[SimulationPlan], filled by the planner only when simulation is requested and not forbidden. Legacy fields (sim_duration, is_simulation_intent, suppress_simulation, wants_steady_state) stay populated for existing consumers.

    Field Meaning
    action time_course | steady_state | parameter_scan
    biomodel_id validated BIOMD\d{10}/MODEL\d{10} or None (uploaded SBML or search)
    duration_seconds parsed request duration in seconds (default 60.0 only when none stated)
    duration_explicit the user stated a duration
    intervals output intervals (default 100)
    parameter_overrides {name: float} parsed with bounded ast.literal_eval; never silently dropped
    scan_parameter, scan_start, scan_end, scan_points required for parameter_scan; points include both endpoints
    target_species species the user asked to report
    validation_errors typed problems found while planning (e.g. DURATION_OUT_OF_RANGE, DURATION_UNIT_UNSUPPORTED, SCAN_INCOMPLETE); a plan with errors is not executed

    SimulationConstraints on the context (simulation_constraints): simulation_requested, simulation_forbidden, replacement_forbidden, reject_if_parameter_missing, scope (current_turn | investigation). Only simulation_forbidden suppresses simulation; "do not substitute/invent/replace …" sets replacement_forbidden.

    1.2 Task status (AuthoritativeOrchestrationResult.task_status) — F02

    {"task_status": "completed|partial|needs_input|failed|cancelled",
 "requested_operation": "parameter_scan", "executed_operation": "time_course",
 "request_match": false, "reason": "...", "grounding_status": "supported|partial|unsupported|contradicted|not_checked"}

    Emitted in the final result, in the SSE done payload (it carries the whole result), in exports and in the run manifest. The UI shows task status separately from the verification score. A missing dataset or model is needs_input; an executed operation that differs from the requested one is failed with request_match=false.

    1.3 Source coverage (ToolResult.payload["coverage"]) — F11

    Aggregate tools report per-upstream {"status": "ok|success_empty|error|not_run", "error_type": ...} and an aggregate status of ok, partial, success_empty or unavailable. All upstreams failing gives ToolResult.success=False with error_type="UPSTREAM_API_ERROR".

    1.4 Claim verification records (VerificationReport.claims) — F01

    {"claim_id", "claim_type": "clinical|mechanistic|computational|absence", "claim_text", "evidence": [{"source_key", "passage"}], "status": "supported|contradicted|unsupported|not_checked", "reason"}. verification_score stays for compatibility; contradicted claims fail verification; unchecked material claims prevent a "verified" label.
